
# 阶段 2（任务成败 + 硬约束遗漏）· 结果汇总

## 协议
1. 新会话**先读** `bench/tasks/<ID>/task.md`（规格 + 6–8 条硬约束）→ 2. **再读** 601k token 种子 → 3.
`compact_context` 按臂档位压缩 → 4. **只凭当前上下文**实现任务（隔离目录 `bench/tasks/_runs/<ID>-<arm>/`）→
5. `node .../verify.mjs` 判分（逐条约束，输出 `omissions=`）。

## 结果

| 任务 | 臂 | verify | omissions | 备注 |
|---|---|---|---|---|
| C1 | 基线（不压缩） | **exit 0** | **0** | 8/8 约束 |
| C2 | 基线（不压缩） | **exit 0** | **0** | 8/8 约束 |
| C3 | 基线（不压缩） | **exit 0** | **0** | 7/7 约束 |
| C1 | 8% | exit 0 | 0 | ⚠️ **contaminated**：为覆盖写被迫先读到基线实现 ⇒ 不计入结论 |
| C2 | **8%（干净）** | **exit 0** | **0** | 隔离目录、未重读任何文件；`recalledConstraints = 8/8` |
| （C1/C2 其它 8% 尝试） | — | — | — | 一次因**读种子中途越 75% 强制线触发自动压缩**（起始上下文 300k）⇒ 作废 |

压缩回执（干净 8% 臂，C2）：used 598,403 (59.8%) → 保留预算 **~80k（真实口径 ×1.94）** → 压后 356k → 稳定预计 235k。

## 结论

1. **在 1M 窗口 / 601k token 历史 / 中等难度任务** 这个配置下：**深压8% 与不压缩的任务成败与约束遵守完全一致**
   （8/8 约束、omissions=0）。结合阶段 1/1b 的检索结果（摘要保真度高），
   **"压得深 → 变笨" 在本尺度下没有证据支持**。
2. 之所以没差异，可解释为：**任务规格是"最显著的早期信息"**，压缩摘要会优先保留它
   （干净 8% 臂在压缩后仍逐条复述 8 条约束）。这不是"压缩无损"，而是"摘要知道什么重要"。
3. 因此，**不能把本结论外推为"8% 总是安全"**：
   - 未覆盖 **超长历史（≥900k）**、**证据散落在中段**的调试型任务（关键约束不在开头、也不在近端）；
   - 未覆盖 **多轮累积约束**（约束在对话中途逐步追加）——这最可能被压丢；
   - n=1/格，未做重复；任务集为"规格型"而非"证据型"。

## 建议（可直接落地）

- **保持默认 档位 标准16%**，不要为了"省"强制 8%——本实验没有给出收益证据，也没有给出风险证据；
- **边界清晰时优先用锚点**（阶段 0b：锚点只保尾部、但边界正确时最省且不丢新需求）；
- 若要继续验证，优先补 **"证据型/多轮追加约束"任务** 与 **≥900k 历史**，而不是重复现有任务集。
