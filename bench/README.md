# bench/ —— 压缩档位实验（阶段 0/1/2）

目标：验证「8% / 16% / 24% / 语义锚点」是否影响**任务成功率与约束遵守**，而不只是压缩后的 token 数。
依据：`docs/context-compression-reasoning-investigation-2026-10-26.md` §9（该报告明确**未**执行真实 A/B）。

> ⚠️ **执行位置**：本实验必须在 **DSH 会话内**运行（插件只在 DSH 里存在）。
> **不能走派发台**——派发台跑的是外部引擎 CLI（ZCode/OpenCode/Qoder），那里没有本插件、没有档位压缩，
> 派过去测到的是"另一个引擎"，与要验证的问题无关。派发台只用于**生成素材**与**设计评审**。

## 三阶段

| 阶段 | 内容 | 模型调用 | 执行者 | 产出 |
|---|---|---|---|---|
| **0 离线保留分析** | 用真实范围选择逻辑回放每个臂，统计"哪些消息/关键事实仍以原文存在" | **0** | 本机脚本 | `retention-probe.mjs` 的表 |
| **1 检索探针** | 同一份种子历史压到各档后，问 12 道事实题 + 4 道对照题 | ~30 次 | **你在 GUI 手工跑 3–4 个会话** | `runs/phase1-*.json` |
| **2 任务 A/B** | 8–12 个可自动判分任务 × 4 臂 × 2–3 次重复 | 48–96 runs | **你在 GUI 手工跑**（需预算） | `runs/phase2-*.json` + 成功率表 |

## 文件

| 文件 | 说明 |
|---|---|
| `gen-seed.mjs` | **生成器**（确定性）：产出 `seed.md` / `seed.json` / `questions.json` / `answers.json`。由派发台生成 |
| `seed.md` | 约 240k 字符的中文开发历史，含 12 个唯一标记的关键事实 |
| `seed.json` | 结构化种子（messages + needles 位置），阶段 0 的回放输入 |
| `questions.json` / `answers.json` | 12 道事实题 + 4 道对照题（对照题答案必须是「不知道」） |
| `retention-probe.mjs` | **阶段 0 脚本**：离线回放各臂，输出「臂 × 深度」事实保留表 |
| `tasks/` | **阶段 2 任务集**：`A1–A4`（独立新任务）、`C1–C4`（6–8 条早期硬约束），各带 `verify.mjs` |

## 阶段 0（现在就能跑，零成本）

```powershell
node bench/gen-seed.mjs            # 生成种子（若还没生成）
node bench/retention-probe.mjs     # 真实种子
node bench/retention-probe.mjs --smoke   # 迷你样本，仅验证脚本链路
```

看什么：
- **事实保留**列：12 个关键事实中仍以**原文**存在几个（信息损失的上界）；
- **远端/中段/近端**三列：不同深度的事实各自保留多少；
- 锚点臂与同预算档位臂的对比（锚点的价值 = 少丢近端、多丢无关远端）。

## 阶段 1（检索探针，人工 30–40 分钟）

每个臂开**一个新会话**（不能在同一会话里顺序压，历史已被改变）：

1. 让 agent 完整读取种子：`读取 F:\My Code\dsh-context-pilot\bench\seed.md 全文，不要总结、不要摘要`;
2. 调 `compact_context`：**先 `action:'set-tier'` 登记该臂档位**，再立即压缩（或用卡上的指引压缩）；锚点臂改为带 `keepFrom:{recentUser:1}`；
3. 发统一题面：
   > 只根据**当前上下文**回答以下问题，逐条写 `Q编号: 答案`；确实不知道就写 `不知道`，不要猜。
   > （把 `questions.json` 里 12 道 + 4 道对照题贴进来）
4. 把最终回答保存为 `bench/runs/phase1-<臂>.json`（`{ "arm": "8%", "answers": { "Q01": "...", ... } }`），我来自动判分（精确匹配，不用模型打分）。

判分口径：`Q0x` 答案需与 `answers.json` **精确匹配**（允许前后空白差异）；`C0x` 必须恰好是「不知道」（用来抓幻觉）。

## 阶段 2（任务 A/B，需预算）

- 每个 run：同一份压缩前状态 → 设该臂档位 → 压缩 → 把 `tasks/<ID>/task.md` 的正文作为唯一指令 → 结束后跑
  `node bench/tasks/<ID>/verify.mjs` 判分。
- 记录（`bench/runs/phase2-*.json`）：`{ task, arm, repeat, verifyExit, omissions, turns, wallSec, inputTokens, outputTokens, compactPath, stableRatio }`。
- **控制**：同一模型/provider/思考强度/工具/温度；压缩时**不换**思考档位；各臂从同一快照独立分支；
  run 顺序随机化；`stableRatio` 要等 provider 刷新后的稳定值（**不拿表盘过渡值比较**）。
- **决策规则（事先定好）**：主指标任务成功率；8% 相对 24% 下降 ≤5pp 视为非劣，且总 token 降 ≥25% ⇒ 默认改 8%；
  劣化 >5pp ⇒ 保持 16% 默认；24% 反而更差 ⇒ 强化"边界清晰用 8%"；无显著差异 ⇒ 保持 16% 默认 + 按边界用锚点。

## 已知限制

- 阶段 0 只能测"原文是否还在"，**测不到摘要质量**（摘要由模型生成）；
- 官方 overflow 兜底路径保留≈0（历史实测 367,794→8,603 token），本实验不覆盖该路径；
- 阶段 1/2 的每次 run 都是独立会话 ⇒ 会话间存在模型侧非确定性，必须重复 ≥2 次。
