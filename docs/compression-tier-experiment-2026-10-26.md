# 压缩档位实验报告（8% / 16% / 24% / 锚点）

> 2026-10-26 ｜ 执行位置：DSH 会话内（team agent）｜ 与插件代码**完全隔离**的 `bench/` 脚手架
> 依据：`docs/context-compression-reasoning-investigation-2026-10-26.md` §9（该报告明确未做 A/B）

## 1. 问题

插件的三档（深压8% / 标准16% / 浅压24%）与语义锚点，**是否影响任务成功率与约束遵守**？
已知：档位只改变"近端保留范围"，摘要质量与档位无关；插件记录能证明调用/执行/token，**不能**证明质量。

## 2. 方法（四阶段，逐步收敛成本）

| 阶段 | 做法 | 模型调用 | 关键设计 |
|---|---|---|---|
| **0 离线保留** | 用真实范围选择逻辑回放各臂，统计"哪些消息/关键事实仍以原文存在" | 0 | 纯函数：`resolveTier` → `scaleRetainBudget` → `selectRange`（**执行侧同一函数**） |
| **1 检索探针** | 601k token 种子 → 按档位压缩 → 12 道事实题 | 3 臂 | 同一份种子、同一批题、n=1 |
| **1b 逐字探针** | 加 12 个"逐字"埋点（代码行/命令/栈行/JSON 键序…） | 3 臂 | 检验"原文丢失"是否成为质量损失 |
| **2 任务成败** | 3 个可判分任务（8/8/7 条硬约束）+ 基线对照 | 基线 3 + 8% 1 | **任务规格先读**（使其成为"早期信息"）→ 读种子 → 压缩 → 实现 → `verify` |
| **3 证据型** | 6 条**无标记**证据埋在 20%–75% 深度，要求逐字取回 | 基线 1 + 8% 1 | 修正 1b 的"显著标记"缺陷；2 道对照题防编造 |

种子：601k token 的真实风格中文开发历史（12 要点埋点 + 12 逐字埋点 + 6 证据埋点，全部全文唯一、确定性生成）。
判分：确定性脚本（要点双向包含 / 逐字原样包含 / 证据原样包含 / 对照题必须含「不知道」类词）。

## 3. 结果

### 3.1 离线（阶段 0 / 0b）

| 臂 | 预算 | 要点埋点保留 | 逐字埋点保留 |
|---|---|---|---|
| 8%（×1） | 80k | 2/12 | 3/12 |
| 16%（×1） | 160k | 3/12 | 4/12 |
| 24%（×1） | 240k | 5/12 | 6/12 |
| 锚点 recentUser:1 | 40k | 0/12 | 1/12 |

### 3.2 检索（阶段 1，n=1）

| 臂 | 事实题 | 对照题 | 压缩回执 |
|---|---|---|---|
| 8% | 11/12 | 4/4 | 保留 ~80k，真实口径 ×1.95 |
| 16% | **12/12** | 4/4 | 保留 ~160k，×1.96 |
| 24% | **5/12** | 4/4 | 保留 ~240k，×1.94 |

⇒ **非单调**（24% 最差）。24% 臂只答出近端 70–93% 的埋点、远端全「不知道」；8%/16% 臂反而从摘要里取回了远端事实。
**n=1 时摘要生成的方差与档位效应同量级。**

### 3.3 逐字（阶段 1b，n=1）——**本次作废**

三臂逐字题**均 12/12**。原因（我方设计缺陷）：埋点写成 `【逐字记录】value` 的显著标记，**摘要器照单保留**；
且 `arm-b8` 交代其答案来自"上下文里自写的进度摘要"。⇒ 该轴失效。

### 3.4 任务成败（阶段 2）

| 任务 | 臂 | verify | omissions |
|---|---|---|---|
| C1 / C2 / C3 | 基线（不压缩） | 全 exit 0 | **全 0**（8/8、8/8、7/7） |
| C2 | **8%（干净）** | exit 0 | **0**（8/8，`recalledConstraints=8`） |

干净 8% 臂：used 598,403 (59.8%) → 保留 ~80k（×1.94）→ 压后 356k → 稳定预计 235k。

### 3.5 证据型（阶段 3）

| 臂 | 证据（6） | 对照（2） | 备注 |
|---|---|---|---|
| 基线（不压缩） | **6/6** | 2/2 | 首答即对 |
| **8%（最激进档）** | **6/6** | 2/2 | E3 首答为 `6`、经判分器提示后补全为 `CONCURRENCY=6`（其余 5 条首答即对） |

证据深度 20%–75%、无任何标记、且不在任务说明里出现。

## 4. 结论

1. **在 1M 窗口 / 601k token 历史 / 中等难度规格型任务** 下，**深压8% 与不压缩在任务成败、约束遵守、
   证据取回上没有可测差异**（甚至埋在中段、无标记的证据也能取回）。
2. 原因不是"压缩无损"，而是**摘要知道什么重要**：任务规格与结论型证据是显著信息，摘要会优先保留。
   这也解释了阶段 0 的"原文只剩 2/12"与阶段 3 的"6/6"并不矛盾 —— **原文丢失 ≠ 信息丢失**。
3. **不能外推**为"8% 总是安全"：
   - 未覆盖 **≥900k 超长历史**（本次 601k，占窗口 60%）；
   - 未覆盖 **证据散落 + 与大量相似干扰并存**的调试场景；
   - 未覆盖 **多轮逐步追加的约束**（约束在对话中途陆续出现，而非开头一次性给出）；
   - 每格 **n=1**，未做重复；阶段 1 的 24% 臂异常即方差示例。
4. **档位不是质量杠杆**：本次所有阶段里，真正决定"信息是否还在"的是**摘要器**，而档位只决定原始尾部长度。
   这与原报告的判断一致：应优先修正展示与决策歧义，而非强制某档。

## 5. 建议

- 默认保持 **标准16%**；边界清晰时**优先用锚点**（阶段 0 显示锚点只保尾部，边界正确时最省且不丢新需求）；
- 不要为了省额度强制 8%，也不要以"多留更安全"为由一律 24%——两者都无数据支持；
- 若要继续验证，优先补：**≥900k 历史**、**证据 + 强干扰**、**多轮追加约束**三类场景，且每格 **n≥3**。

## 6. 本轮踩到并修掉的 5 个方法学陷阱（供后续实验复用）

| # | 陷阱 | 症状 | 修法 |
|---|---|---|---|
| 1 | `verify` 找不到 `solution/` 会**回退 `ref/`** | "全过"是参考解的功劳 | 隔离运行目录（复制 task/verify/fixture，不带 `ref/`）+ 强制检查产物存在 |
| 2 | 复用 `solution/` 目录 | `write` 先读后写 ⇒ 实验臂读到基线实现 | 每臂独立目录；该数据点标 `contaminated` |
| 3 | 起始上下文过大时读 601k 种子 | 中途越 75% 强制线触发**自动压缩**（used 仅 237k） | 用上下文最小的成员；读取后总占用须 < 75% |
| 4 | 埋点用显著标记（`【逐字记录】`） | 摘要照单保留 ⇒ 测的是摘要保真度 | 埋点必须**无标记**、混在普通叙述里 |
| 5 | 判分器失败信息**打印期望值** | agent 自己跑 verify ⇒ 自我校正 | 失败信息只说"缺失/不匹配" |
